## Research reassessment

Canonical's snapshot identifier fixes archive state and must be selected by release authority rather than an installation clock: <https://ubuntu.com/server/docs/how-to/software/snapshot-service/>.

APT's native chain remains authoritative. A valid `InRelease` authenticates exact index size/SHA-256 entries; `Packages` authenticates each selected `.deb`; `Sources` authenticates each selected `.dsc` and source object; and the `.dsc` checksum inventory must agree with the admitted non-`.dsc` source objects: <https://manpages.debian.org/testing/apt/apt-secure.8.en.html>, <https://wiki.debian.org/DebianRepository/Format>, and <https://www.debian.org/doc/debian-policy/ch-source.html>.

The DevBridge Ed25519 signature binds the already verified exact capsule subject. It does not replace or weaken Canonical provenance.

## Nested LEGO design

1. A pure Ubuntu capture verifier parses bounded clear-signed metadata and Debian control indexes, checks the caller-pinned Canonical signing fingerprint through an injected detached-signature port, and proves every admitted metadata, binary, and source object against its upstream size/SHA-256 record.
2. A topology-neutral local-file publisher measures each nonsymbolic unlinked regular file once, emits fixed ordered chunks, and publishes chunk bytes by digest inside a newly created operation-owned directory.
3. The Ubuntu release sealer composes those children, constructs the three DB-HO129 immutable-object descriptors, verifies the upstream chain, signs the normalized release, self-verifies the manifest, and publishes manifest/public key last.
4. A thin release-operator CLI reads bounded explicit recipe/key/keyring inputs. It has no origin, credential, upload, setup, provider, VM, or construction option.

No child may silently infer a snapshot, package, key, origin, path, or timeout policy. Unknown fields and ambiguous mappings fail closed.

## Failure, recovery, and cleanup

- Input files must be absolute, nonsymbolic, single-link regular files and must remain the same observed filesystem objects while read.
- An existing output directory is caller-owned and is never reused or removed.
- All generated bytes stay below one newly created operation directory. Any interruption or verification failure removes only that directory.
- Content-addressed chunk publication occurs before manifest/public-key publication. The signed manifest is never left beside incomplete objects.
- No timeout change is part of this slice.

## Local implementation and qualification checkpoint

The implementation keeps four nested owners:

- `immutable-object-file-publisher.mjs` holds direct local input files while measuring and publishing fixed digest-named chunks;
- `gpgv-inrelease-verifier.mjs` invokes one explicit absolute `gpgv` executable against one explicit direct keyring and accepts exactly one caller-pinned valid signing fingerprint;
- `ubuntu-package-capsule-capture-verifier.mjs` verifies the signed pocket/codename/architecture/component identity, `InRelease` index hashes, `Packages` binary hashes, `Sources` source hashes, and `.dsc` file inventory;
- `ubuntu-package-capsule-release-builder.mjs` composes those children, signs only after native-chain verification, canonicalizes the manifest, self-verifies it, and publishes manifest/public key last.

The CLI exposes only explicit recipe, output, key, `gpgv`, keyring, and chunk-size inputs. It has no origin, credential, upload, setup, provider, VM, construction, or installation option. The default index decoder accepts plain or gzip indexes and fails closed on xz unless a separately explicit decoder is supplied; release capture can select the gzip indexes already exposed by the Ubuntu archive.
