## Implementation and qualification

Implemented in the existing construction parent, request contract, ledger and management channel. Data-bearing state uses v3; old v2 records remain readable, but data fields in v2 or malformed v3 data fail closed. Record validation is injected from the owning request contract, not duplicated in persistence. Presence/absence and exact data identity cannot change after durable intent. Media is admitted before provider preparation and reobserved before install start. Fixed provider slots remain internal; the caller cannot name a DVD/controller/VM/disk. Shared native attachment validation prevents unknown paths, duplicate slots or extra devices from being silently attached, started or removed. Exact remaining subsets can be reconciled after interrupted detachment; removal readback precedes firmware/start changes.
