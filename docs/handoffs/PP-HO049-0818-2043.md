## PP-016 design selected for #49 multi-agent coordination

PP-016 is the normative contract for this slice.

Key design decisions already established:

1. **Persistent cryptographic installation identity**
   - Local Ed25519 keypair lives in PATCH-POLLER control state.
   - Public identity fingerprint is lowercase SHA-256 over the DER/SPKI public key.
   - Public address is `<handle>#<64-hex-fingerprint>`.
   - Private key material is never projected into task/repository/GitHub/model contexts.
   - Hardware serials, MAC addresses, hostnames, project paths, and similar machine strings are not used as secret key material.

2. **Signed task-lease subject**
   - `patch-poller/task-lease-v1` binds queue repository, issue number, exact task revision, owner fingerprint/address, daemon session ID, fencing epoch, active/released state, issuance/expiry, and exact predecessor lease SHA.
   - Lease signatures authenticate coordination peers only; they do not become a second task-command authority.

3. **Authoritative distributed claim primitive**
   - Labels/comments may later mirror lease state for humans but are not exclusivity authority.
   - The authoritative lease is a dedicated queue-repository Git ref.
   - Lease transitions use explicit expected-value Git CAS with `--force-with-lease=<ref>:<expected-sha>`.
   - First creation uses an explicitly empty expected value; later transitions bind the exact previously observed lease commit.
   - Blind `--force`, an unspecified force-with-lease expectation, or label/comment races are not accepted as equivalent authority.

4. **TTL, heartbeat, reclaim, and fencing**
   - Active leases renew on a bounded heartbeat shorter than TTL.
   - Trusted peer leases may be reclaimed only after signed expiry plus configured clock-skew margin.
   - Definite CAS loss fences the local holder and aborts its child-process execution context.
   - Ambiguous network/renewal failure does not pretend ownership moved, but the local claim becomes unusable when its signed expiry is reached.
   - Terminal release is a signed CAS transition to `released`, not blind ref deletion.

5. **Same-identity session rule**
   - Persistent fingerprint and daemon session ID are distinct.
   - An unexpired lease from the same fingerprint but a different session is treated as `held-by-local-session` unless the local control path has separately proven process exclusivity.
   - `createRuntime` exposes the local-only `coordinationExclusive` option.
   - `runDaemon` acquires the existing exclusive `state.directory/daemon.lock` first and then creates runtime with `coordinationExclusive: true`.
   - Ordinary `runOnce`/non-exclusive runtime creation does not receive same-identity takeover authority and therefore must wait for expiry rather than stealing an unexpired local-session lease.

6. **Candidate branch isolation**
   - When coordination is enabled, the full persistent fingerprint is inserted beneath the configured PATCH-POLLER branch prefix.
   - Coordination-disabled deployments retain the legacy branch naming behavior.
